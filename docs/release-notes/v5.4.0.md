<h2 align="center">Release v5.4.0 — The capability ecosystem </h2>

## What's New Since v5.3.0
Capabilities now travel as single sealed files — person-to-person, over
Discord, a release, a USB stick or an airgap — with attribution, a
safety scan and a review wizard before any code runs.

## What landed

**Packages: `.sjm` / `.sja` / `.sjp`** — three kinds, one container
spec: module packs, zero-boilerplate addons and tier-gated kernel
plugins. `suijin pack build <dir>` seals a pack (the tool table is
auto-extracted from your actual code, an invalid manifest tools map is
auto-filled, your dev note rides inside) and prints the outer SHA-256
to publish alongside it. `suijin install <file>` runs the wizard: who
built it and when, the dev note, the safety-scan verdict, every tool it
adds, any external binaries it calls — Enter installs.

**The built-in safety scanner** — AST-only, so it can never execute
payload code (tested with an import-time `os.system` sentinel: zero
effects while scanning). Critical findings — hidden `eval`/`exec`
including string-multiplication obfuscation blobs, hardcoded secrets in
source assignments, built-in tool-name shadowing — refuse the install
unless `--allow-unsafe`. Warnings — undeclared process spawning, network
egress, import-time effects — show on the card; declared binaries are
honest metadata, not findings. Install ALWAYS re-scans source: the
build-time report embedded in the package is advisory for browsing,
never trusted.

**Seals and guards, each with its own test** — any in-transit byte edit
refuses and names the file (SHA256SUMS inside every archive); path
traversal, symlink entries and zip bombs refuse outright; a public
function named like a built-in tool (`http_request`, `nmap`, …) is
REFUSED — the loader's tool namespace is flat and a shadow would be a
supply-chain takeover; `tier: core` plugins cannot be installed.

**Malicious examples, shipped as proof** — `examples/malicious/` carries
five hostile packs (eval_snake, creds_leaker, obfuscated_shell,
tool_shadower, sneaky_spawner). Building them exposed and fixed two real
scanner gaps (source-style secret assignments, multiplication-built
blobs); CI now builds each and asserts the installer refuses or flags
it, forever. Three clean examples — `headerpeek`, `wordsmith`,
`bootbanner` — are sealed in `examples/built/` ready to install.

**Field fixes riding along** — the thinking spinner runs at 3× the
default frame rate (measured; the earlier "speed" values had Rich's
multiplier semantics backwards and were slowing it down), RunBox shares
the engagement console (its private one interleaved mid-refresh with the
live strip), and the core_utils `search_kb` shim accepts its documented
`limit` argument (flat-namespace shadowing made every documented call
throw). The wizard's outer-hash line lets anyone verify a downloaded
package against the author's published hash.

## Try it

```bash
suijin install examples/built/headerpeek-1.0.sjm   # wizard → Enter
suijin pack build ./my-pack --note "what it does"   # your own
```

The author-facing format spec lives in `docs/sjpkg-spec.md`.
