# v6.8.0 — Crash-Proof Engagements

The field rule this release enforces: **an engagement that ran is an
engagement you can resume.** No exit path — random crash, teardown
failure, kill signal, interpreter death — is allowed to leave nothing
on disk. And once the bundle exists, nobody should have to memorize a
timestamped filename to get back in.

### An .sje for every exit
A crash-saver arms the moment the engagement's thread exists, before
anything below it can fail. Five paths funnel into ONE idempotent
once-flagged save:

- the normal conclusion save
- the `finally` backstop (a crash or Ctrl+C *inside* the final-report
  block used to skip the bundle silently — an unprotected write was
  enough)
- SIGTERM/SIGHUP (chained *after* the FULL-AUTO handler, so unattended
  docker-stop keeps its graceful pause-and-save semantics)
- `sys.excepthook` — setup-phase crashes that sit outside every try
- `atexit` — interpreter exit, `sys.exit`, menu-level death

The once-flag is claimed *before* the zip is written, so a crash inside
the emergency save cannot re-enter. The state getter is late-bound: the
provider-restart latch rebinds `agent`/`thread_id` mid-run and the
saver follows automatically. One engagement, one bundle — a backstop
firing after the conclusion save is a no-op, not a second file.

### `suijin load` picks, you don't memorize
Bare `suijin load` lists the ten newest bundles — date, size, cost,
objective — newest first:

```
  Recent engagements (newest first):
    1. 2026-09-20 04:12    41KB $1.27  CTF challenge at http://localhost:1337
    2. 2026-09-19 22:40   187KB $0.49  Bug bounty recon on api.example.com
   ...

  resume which [1-10, or a path/name, blank=1, q=quit]:
```

Pick a number, type a bare name (resolves from the exports inbox with
or without the `.sje` suffix), or paste a full path. Non-interactive
runs (CI resume) take the newest automatically. The Operator Tools →
Resume menu entry opens the same picker.

### Resume-config hardening
Bundles store config with sensitive keys stripped to `***stripped***`.
The resume merge used to let those markers through — a stale
placeholder could override a good default for any key the operator's
live config.json doesn't pin. Markers are dropped at resume; the live
config fills the hole. Engagement STATE rides the bundle; operator
SETTINGS ride config.json — now without exceptions.
