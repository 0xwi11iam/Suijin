<h2 align="center">Release v5.6.1 — Installability Fix </h2>

## What's New Since v5.6.0
One bug, one crash, one promise: `pip install suijin` works on a clean
machine, the container boots and takes verbs, and un-installable
metadata can never ship again.

## What landed

**The pip fix** — the 5.6.0 wheel declared `rich<14` alongside
`textual>=8` (which requires `rich>=14.2`): an unsatisfiable pair that
made every fresh `pip install suijin` die with `ResolutionImpossible`.
The dev environment never saw it because pip doesn't re-check
already-installed packages against new bounds. Bounds are now
`rich>=13,<16`, and textual ships in the container image so the Module
Manager TUI opens there too.

**The container fix** — `docker run ghcr.io/0xwi11iam/suijin` crashed
with `ModuleNotFoundError: No module named 'suijin'`: the entrypoint
imported the package before putting its parent on `sys.path`. The
bootstrap now runs first, and known CLI verbs dispatch headless —
`docker run image version`, `doctor`, and every other subcommand work
straight from the entrypoint. The image also passes its own healthcheck
now (`feroxbuster` + `john` were missing from the curated tool list).

**Blue console polish** — the stats strip has a heartbeat (uptime ticks
and the spinner never freeze between requests), the command affordance
row is always visible, and baseline training renders one dim progress
line instead of scrolling the console with banners.

**The promise** — publishing is gated by a clean-venv proof: the wheel
is built, installed into a fresh environment, and the CLI runs before
anything uploads. The bug class that shipped 5.6.0 is now a build
failure, not a user's error report.

## Try it

```bash
pipx install suijin                     # or: pip install suijin
docker run --rm ghcr.io/0xwi11iam/suijin:latest version

```
