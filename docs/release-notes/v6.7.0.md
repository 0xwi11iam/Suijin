# v6.7.0 — The Hardening Release

The run loop cannot die, the model can see its own tools again, the
engagement remembers what it found, and the bill stops paying for
invisible tool lists. This is the release where the field reports
became fixes.

### THE TOOL-VISIBILITY FIX (the agent reported it itself)
The token diet silently dropped the evidence engine from the model's
tool list — mid-engagement the agent said: *"catalog_exploit doesn't
exist in my tool list."* It was right: catalog_exploit, memory_recall,
http_replay, inject_probe, web_session, coverage_check,
dispatch_testers, surface_expand, bypass_403 and code_harness were
invisible. All ten are registered and rendered again (catalog 9.2k
chars, still −48% from the pre-diet 17.6k), and the engagement order
now speaks v3 POC (sequential commands + expected_result — not the old
step-script/marker vocabulary).

### The run loop cannot die
Three single-line structural bugs each turned a designed self-heal into
a silent engagement death — all fixed, all behaviorally tested for the
first time:
- the provider-restart latch `continue`d the wrong loop: the restart
  was fiction, every provider flake killed the run → now a true resume
  with state carried across the rebuild
- the unreachable `while…else`: a stale .sje resume ended as a FALSE
  "check your provider key" no-output diagnosis → real post-stream
  recovery
- Ctrl+C landing inside a graph node ENDED the engagement instead of
  pausing (pause was probabilistic on stack timing) → the sentinel
  checks the interrupt flag, always

Plus: model-authored `job_wait(timeout=3600)` can no longer freeze the
whole pipeline (clamped, off the event loop); malformed stream events
skip-and-log; resume bundles are schema-validated; a dead input reader
can't deadlock a pause or stall an ask; ask_operator REALLY pauses (the
answer lands THIS turn, not a turn late); .sje saves are atomic; parse
garbage escalates (temperature ladder) then self-heals instead of
killing 200 iterations of work; and the no-progress breaker ends
valid-but-empty decision loops cleanly instead of billing forever.

**The fuzz harness**: hostile streams — event soup, fake restarts,
mid-graph interrupts, seeded random storms — with one invariant: every
run returns a classified outcome. It caught two real bugs before
shipping (a non-TTY crash, a thread-stacking hang).

### The POC system v3
- A NEW FOLDER per exploit: `finding.md` (uniform dossier) +
  `exploit.yaml` (sequential shell commands + Expected_result)
- The verifier TAKES OVER the run loop: numbered command panels,
  black-box output, the AI paused, the input box stays live — bounded
  by its wall cap
- On miss: the full copy-paste transcript + exactly THREE options —
  edit the yaml / rewrite (memory-poisoned) / worked-anyway with a
  VERIFIED evidence line (fabricated lines are rejected)
- Anti-hallucination gates intact: echo-block, target-reference,
  marker quality, AI_CLAIMED cap, system-side severity

### Session memory — the librarian
A daemon thread watches every tool result: credentials, secret leaks,
footholds, confirmed exploits, error oracles, admin/upload surfaces —
pattern-first, zero LLM — into a deduped ledger, with a rare condensed
digest. The recall contract: **cool things found at hour 0 surface the
moment a matching target appears** (every-turn relevant block) plus the
`memory_recall` tool. The ledger, scratchpad and attack queue ride .sje
resumes. Cross-engagement memory revived (what_worked read a dict as a
list — always empty; the recall text was computed then discarded for
361 sessions). Context windows resolve via the models.dev catalog with
the 1M fallback; budgets, compaction triggers and the output cap scale
off it; the strip shows live `ctx %`.

### The token diet
Measured: ~16.5k input tokens/turn steady-state before. Catalog
one-liners (17.6k→9.2k chars), head+tail result digests offloaded at
8k (one big result used to eat the whole 24k embed every turn),
task-scoped subagent tool references (a fireteam burst shipped ~390k
tokens of tool lists alone), and a byte-stable prompt head so
provider-side prefix caching can actually hit.

Kimi intl+CN, Qwen DashScope intl+CN, Volcengine Ark, StepFun,

### The Textual Settings TUI
Curses is gone. Grouped field list + typed editors (Switch/Select/
Input with clamp-on-save), provider swap rebuilds the visible fields,
Save/Cancel always visible, echo-proof saves (the async-Changed race
that wrote field A's value into field B is structurally dead — one
mounted editor per field), corrupt configs refuse save instead of
wiping.
