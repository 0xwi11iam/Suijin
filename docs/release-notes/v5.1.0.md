# Suijin v5.1.0 — Desktop (technical preview)

The agent gets a GUI. The GUI contains zero agent code.

## What landed

**The gateway** (`suijin gateway`) — the core grows a typed API
surface: everything the CLI can do, over authenticated HTTP/WebSocket.
Per-boot bearer token, localhost-bound by default, and the only writes
are explicit operator decisions (approvals, ask-operator answers,
launching an engagement). Its OpenAPI schema is the contract —

**The desktop app** (`desktop/`) — a Tauri + React + TypeScript
client generated against that contract:

- **Approvals inbox** — when the agent blocks on a dangerous action,
  a card appears: the command in a code block, impact assessment,
  Approve / Deny. Click, and the running agent resumes. The
  ask-operator inbox answers the agent's questions inline.
- **Engagement** — launch the red agent (objective + target +
  template), then watch every tool call stream live from the audit
  trail, with the cost ticker running in the header.
- **Dashboard** — units/tools/KB at a glance, spend with
  api-vs-estimated accuracy, the arsenal by owner, knowledge-graph
  targets.

**The design** — cold cyan on near-black, a radar instrument: cyan is
reserved for live/active moments. Instrument Serif for display
numerals, Geist for UI, Fira Code only inside code blocks. Fonts are
OFL-licensed; app icons generated from the project's own logo.

## Why this architecture

The app is a *client* — so it works against a gateway on this machine
or a Kali box in Docker, the terminal remains a first-class surface,
the kernel stays pure, and the TypeScript types are generated from the
gateway's own schema (drift is impossible by construction).

## Try it

```bash
suijin gateway          # prints the token
cd desktop && npm install && npm run dev
# paste the token, connect
```

1,245 tests green; desktop builds clean under strict TypeScript; the
gateway suite pins the 401 matrix, route contracts, HITL round-trips,
and the OpenAPI schema.
