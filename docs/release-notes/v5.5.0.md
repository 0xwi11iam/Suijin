<h2 align="center">Release v5.5.0 — Harness competence </h2>

## What's New Since v5.4.0
Six repairs to the decision loop itself, every one traced to a real field
run — not new tools, not benchmark tuning: the brain the tools run on.

## What landed

**The engagement state board** — the agent had amnesia: its target
intelligence was set once at launch and never written again, so it
re-derived its own attack surface every ~8 actions. Now every successful
tool output feeds the board (ports and services from nmap, endpoints from
bundles and requests, tech from headers, credentials, subdomains), and
the board — with the tested-axes coverage map and any running background
jobs — renders in the agent's context every single turn. Chaining finally
has a foundation.

**Results stop vanishing** — a field run found a leaked API key, put the
scan in the background, ended the session, and never collected it.
Finished background jobs now walk into the conversation on their own
(same as fireteam results always did); `job_wait` no longer promotes
*itself* into a background job while waiting; `job_status` shows the
full result instead of a 500-character clip.

**The head-bang killer** — one identical failing request was repeated 80
times across nine and a half hours; the prompt's "never repeat a failed
action" rule is a suggestion the model ignores. Now it's a law: three
identical failures of the exact same call hard-block with the last error
and named alternatives. Different arguments always pass — payload
iteration is legitimate work. And the "Recent Failures" prompt section,
initialized but never written since it existed, finally has data.

**The control plane woke up** — 51 expert skill playbooks sat behind a
switch the model was never told about (zero switches in every session
ever recorded). `switch_skill` and `plan_tools` are now in the decision
menu with concrete shapes. Multi-step plans no longer lose their steps
after the first executes — the queue stays visible and drains as it
runs. Todos render the IDs the update action matches by. And two new
prompt-hygiene CI gates make ghost tools impossible: every tool name
the prompt teaches must exist in the booted registry, or the build
fails — not a field run.

**Claims get proven, lessons get kept** — findings are now verified at
the moment they're claimed (independent second check, verdict on the
result line), the verification recipe library grew from five classes to
ten, and the keyword-mention "verified" fallback — which manufactured
confidence from noise — is dead. Engagement memory was repaired at three
joints (a swallowed TypeError had produced zero memory entries across
361 sessions): prior engagements now recall at start, outcomes record at
end, and the scratchpad suppresses duplicate spam that once hijacked a
run's priorities. Bonus latent fix: HTTP failures were being recorded
as successes in the trace, which is why the failure marker never fired.

**The flight recorder works** — every audit row carried `iteration=?`
since the beginning; per-iteration forensics were impossible. Now they
carry their number.

## Try it

```bash
suijin            # Red Team → objective → run
```

Watch the transcript: the agent's context now shows the board growing
(ports, endpoints, credentials as they're found), background scans
announcing themselves when done, dead calls getting blocked at the
fourth attempt, and finding recordings arriving with a verification
verdict. After the run, `outputs/memory/` holds the engagement record —
the next run against the same target starts smarter.
